## 2. 自编 Steam 采集程序

入口是 `scripts/crawl_steam_reviews_bulk.py`，复用 `crawl_steam_reviews.py` 中的接口请求和页内筛选。请求 Steam 官方公开评测 API，按游戏及推荐/不推荐类别分别分页，要求简体中文，每页至多 100 条。游标指定下一页，不通过页码猜测地址。

每页保存数据、统计、时间及下一个游标，之后才继续请求。逐页检查点在 `data/processed/steam_bulk_pages/`，相同参数重跑可续采。顺序请求至少间隔 1 秒；临时网络错误有限重试，HTTP 429 停止。以空页、无后续游标等判断完成，不能因为一页不足 100 条就认定全抓完。

保留评测 ID、游戏 ID、正文、时间和弱标签，不保留作者资料和 SteamID。原始计数包含未通过筛选的评测，检查点主要保存筛选后的行及页统计，不应宣称完整原始正文已全部归档。

## 3. Python 主要清洗规则

1. 合并连续空白、去首尾空白，遮盖链接、邮箱、常见大陆手机号和部分 @ 名称。基础规则不等于完整匿名化。
2. 核对接口的语言与推荐状态，保留 8—300 字、至少 4 个汉字、ID 合法的短评。这里是中文数量阈值，**不是中文占比阈值**。
3. 以评测 ID 去重，同 ID 内容冲突则排除。
4. 以清洗后的完整正文去重。同文同标签保留一条，同文异标签整组排除。
5. 在训练划分阶段再用标准化正文指纹检查跨来源和跨集合重复，避免同句进入训练和测试。

本次长度/中文含量排除 111,684 条，语言或推荐状态排除 24 条，页内保留 104,647 条。ID 阶段净排除 0 条，正文阶段净排除 1,745 条，得到 102,902 条。正文阶段含 1,522 条同标签重复及 50 组冲突正文；组数不能直接当作排除行数相加。

清洗示例可用人工构造文本：“  游戏很好玩\n联系 test@example.com  ”变成“游戏很好玩 联系 [邮箱]”。需标为示意，不能冒充真实用户原文。

## 4. 标签质量

“推荐/不推荐”是用户对整篇评测的选择，映射为正/负弱标签，不保证短句情感一致。100 条抽样只有 AI 辅助初审：83 条倾向较明确，其中 77 条与原弱标签一致；17 条混合或不明确。未经独立人工复核，不能写“已完成人工标注”。

## 5. PySpark 后续处理与普通 Python 对照

Spark 读取已经清洗好的 Steam JSONL，规范化空白、计算长度，按游戏、标签、UTC 月份、长度桶分组，统计条数和字符总量。普通 Python 对同一输入执行相同任务。没有用 Spark 再完成一套原始评测筛选去重，也没有用 Spark 训练最终模型。

| 输入条数 | Python 中位数 | Spark local[4] 中位数 |
|---:|---:|---:|
| 10,000 | 0.030 秒 | 0.325 秒 |
| 50,000 | 0.150 秒 | 0.365 秒 |
| 102,902 | 0.306 秒 | 0.325 秒 |

各档 3 次、聚合结果一致。包含读取、解析、空白处理和聚合，不含输入准备与 JVM 启动。该任务没有观察到明显 Spark 加速，本机 local[4] 不能代表多机集群。缓存与预热会影响数值。
